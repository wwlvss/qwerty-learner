# 新增功能：英语词根、词缀、词源解析及个人词根知识库

请在之前 Qwerty Learner 个人英语学习系统改造项目的基础上，增加一个完整的「词根词源学习系统」（Word Etymology & Morphology）。

这是原项目的增量开发任务。

此前已经完成了项目架构分析，分析基于以下技术栈：

- React 18
- TypeScript 4.9
- Vite 4
- Dexie 3.2
- IndexedDB
- Jotai
- Tailwind CSS

请先检查当前 Git 工作区、已经完成的功能、未提交修改和当前开发阶段。

**绝对不要覆盖此前已经完成的代码，不要重置 Git，不要重新开发整个项目。**

本次希望实现的学习流程：

单词打字 → 输入正确 → 显示词根词缀 → 解释词源演变 → 查看同源词 → 建立词根知识网络。

## 一、单词正确输入后显示词源卡片

这是本次开发的核心。

在原有单词打字模式中，用户正确输入完整单词后：

1. 正常显示原来的正确输入反馈。
2. 在当前单词的反馈环节增加词源解析卡片。
3. 展示单词的构词结构。
4. 展示历史词源和词义演变。
5. 展示具有真实词源关系的同源词。
6. 展示简洁的中文记忆方法。
7. 用户阅读完成后，可以点击继续进入下一个单词。

不能影响原有打字逻辑、正确率、速度统计和单词记录。

需要增加三种显示设置：

- 自动显示：每次答对后显示词源卡片。
- 首次显示：每个单词第一次答对时显示，之后可以直接进入下一个单词。
- 关闭：不显示词源卡片。

用户可以随时再次打开某个单词的词源解释。

词源卡片不要过度占用屏幕空间，默认采用简洁布局，详细历史解释可以展开。

如果单词没有可靠的词源数据，不要阻塞原有打字流程，显示「暂无可靠词源资料」。

## 二、词源卡片的具体内容

每个单词支持以下信息：

### 1. 基础信息

- 英文单词
- 音标
- 中文释义
- 英文释义
- 词性
- 常见用法

优先复用原项目现有词库，不重复建立基础词典。

### 2. 构词拆解 Morphology

分别解释：

- Prefix：前缀
- Root：词根
- Suffix：后缀
- Stem：词干
- Inflection：屈折变化

例如：

inspect

in-：向内

spect：看、观察

构词理解：向内观察，引申为检查、视察。

需要显示拆解后的结构，并高亮对应的字母部分。

注意：不能为了让所有单词都能拆解而强行制造词根。

对于无法可靠拆解的单词，应明确显示暂无可靠的构词分析。

### 3. 历史词源 Etymology

需要解释：

- 最初来源语言。
- 原始词形。
- 原始词义。
- 进入英语之前的演变过程。
- 现代英语中的词义变化。
- 重要的历史演变节点。

例如：

拉丁语 inspicere → 英语 inspect。

说明其历史上与向内观察有关，后来形成检查、检验的含义。

不要将现代英语的拼写拆分直接当成历史词源证据。

如果历史资料不足，应标记为待核实。

### 4. 同源词 Cognates

展示具有真实历史词源关系的其他英语单词。

例如：

spect 相关词：

- inspect
- inspection
- spectator
- respect
- perspective

每个词显示：

- 英文
- 中文释义
- 与当前单词的词根关系
- 简短构词解释

注意：上述列表应逐词核实历史词源关系，不能仅凭拼写相似就认定为同源词。

将词汇分为：

A. 真正同源词：具有可验证的共同词源。

B. 相同词根构词：通过相同词根形成的不同单词。

C. 语义相关词：意思相近但不一定具有共同词源。

三类不能混为一谈。

点击单词可以查看该单词的详细信息。

### 5. 记忆方法

提供简单、自然的中文记忆方法。

例如：

spect 与观察、观看有关。

看到 spect，可以联想到 inspect（检查）、spectator（观众）。

要求：

- 解释词根如何帮助理解单词。
- 联系常见同源词。
- 避免牵强的中文谐音。
- 不要编造历史来源。
- 区分词源事实和辅助记忆联想。

## 三、建立个人词根知识库

这是第二个重要功能。

不要只让用户在每个单词下面看到词根解释，还要建立独立的「词根知识库」。

新增一个页面：

Root Library / 我的词根库

展示：

- 已学习词根数量
- 已收藏词根数量
- 每个词根的含义
- 对应的英语单词
- 学习历史
- 收藏状态

例如：

spect：看、观察

关联词：

inspect
inspection
spectator
respect
perspective

port：携带、运输

关联词：

transport
import
export
portable

struct：建造、构建

关联词：

structure
construct
construction
infrastructure

以上词汇仅作为功能演示数据，实际关系需要逐一核实。

支持：

1. 点击词根查看详情。
2. 查看关联词汇。
3. 收藏词根。
4. 取消收藏。
5. 搜索词根。
6. 按来源语言筛选。
7. 按学习状态筛选。
8. 查看自己通过哪些单词学到了这个词根。

支持从一个词根进入相关单词，再从相关单词进入其他词根，逐渐建立个人词汇网络。

## 四、建立词源数据结构

在原有 Dexie / IndexedDB 基础上扩展。

先检查当前数据库版本和现有迁移机制。

建议建立以下数据结构：

### EtymologyEntries

保存单词词源：

- id
- wordId
- normalizedWord
- prefix
- root
- suffix
- stem
- morphologicalAnalysis
- originLanguage
- originalForm
- originalMeaning
- historicalEvolution
- etymologyExplanation
- memoryTip
- sources
- confidence
- verificationStatus
- updatedAt

### Roots

保存词根：

- id
- root
- language
- meaning
- originalForm
- explanation
- relatedRootIds
- sources
- confidence

### RootWordRelations

保存词根与单词的关系：

- rootId
- wordId
- relationType
- explanation
- source

relationType 区分：

- cognate
- shared_root
- related_meaning

### RootFavorites

保存用户收藏的词根：

- rootId
- createdAt

要求：

1. 保留原有数据库表。
2. 使用 Dexie 版本迁移。
3. 不清除原有学习记录。
4. 不改变现有单词 ID。
5. 新增数据必须支持本地备份和恢复。
6. 不要把所有词源数据直接塞进原有单词 JSON。
7. 词源数据应与原始词库解耦。

## 五、词源资料来源与词典接入

本次需要重点研究以下资料：

### 1. Wiktionary

https://en.wiktionary.org/

作为词源数据的重要参考。

研究其：

- 词源章节。
- 构词分析。
- 词根关系。
- 相关词条。
- 数据导出与开放许可。

### 2. Etymonline

https://www.etymonline.com/

作为英语历史词源的辅助参考来源。

注意：可以查阅并引用来源，但不能未经许可批量复制其有版权限制的词条内容。

### 3. ECDICT

https://github.com/skywind3000/ECDICT

继续作为基础词典补充：

- 中文释义
- 英文释义
- 音标
- 词性
- 词频

不要将 ECDICT 当作完整的词源数据库。

### 数据接入原则

优先使用可以合法下载、保存和离线使用的开放数据。

对于每条词源资料，保存：

- 来源名称
- 来源网址
- 资料许可
- 原始词条
- 核实状态

不能确认的内容标记为待核实。

不允许通过 AI 自动生成未经验证的拉丁语、希腊语词根和历史演变。

可以使用 AI 辅助解释，但必须把生成内容和有来源支持的历史事实区分开。

首期不需要接入付费 API。
