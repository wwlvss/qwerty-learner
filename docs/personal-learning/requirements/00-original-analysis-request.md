# 最初的项目分析要求（历史记录）

本文件还原本次会话最初的分析范围。最初阶段限定“只分析、不修改代码、不提交 GitHub”；用户之后要求网页试用、持续开发和发布，该阶段限制不应被误解为永久禁止后续开发。当前本地接手范围见 MASTER_HANDOFF.md 与 LOCAL_CODEX_FIRST_MESSAGE.txt。

项目：wwlvss/qwerty-learner，原引用 master。目标：将 Qwerty Learner 改造为个人英语学习系统。

请先全面分析项目，不修改代码，重点检查：

1. 当前技术栈和版本。
2. 单词词库存储位置和数据格式。
3. 释义、音标和发音的实现方式。
4. 打字练习核心逻辑。
5. 学习进度和数据保存方式。
6. 是否已有单词练习历史记录。
7. 是否支持离线运行。
8. 构建、测试和部署方式。
9. 接入 ECDICT、Tatoeba 和 FSRS 的可行性。
10. 如何增加例句填空、完整句子输入和个人薄弱词汇分析。

特别关注：

- 尽可能复用原代码。
- 不破坏现有功能。
- 不无必要升级依赖。
- 新功能不依赖付费 API。
- 必须支持本地学习数据保存。
- 考虑公司电脑没有管理员权限的部署方式。

最初要求的分析交付：

A. 当前技术架构。
B. 需要修改的现有文件。
C. 需要新增的文件。
D. 数据库设计。
E. 词典和例句接入方案。
F. FSRS 接入方案。
G. 分阶段开发计划。
H. 技术风险。

另外，用户在云环境最初请求过 cloud-environment-onboarding:setup。该技能是当时云环境的配置流程，不意味着用户本地 Codex 必须安装同名云插件。当前接手者应适配本地实际工具，不反复索要云环境权限。
